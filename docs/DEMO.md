# 「求真·深读」演示脚本（DEMO）

> 目标：90 秒内让评委看懂「选中一句 → 深读 → 求真/求深/求异 → 继续探索」的完整闭环。
> **V1.5 增量**：新增「悬浮球 → 全文理解 → 主动发现声明 → Hover 交互」链路，演示见文末。

## 准备

1. 项目根放好 `deepseek_api.key`，运行 `node scripts/gen-config.js`
2. Chrome 打开 `chrome://extensions` → 开发者模式 → 加载已解压的扩展程序 → 选择仓库根目录
3. （可选）放置 `zhihu_api.key` 并重跑 gen-config → 底部显示「已核验」+ 检索来源链接；无凭证则显示「未联网核验」（降级态，演示同样成立）
4. 打开演示页（推荐知乎问答 / 新闻长文 / 技术博客，选一段有观点、有数据、可质疑的内容）

## 演示流程

### ① 低打扰入场（10s）
> 话术：正常阅读时，插件几乎不存在——不做弹窗、不采集整页。

演示：打开一个网页正常滚动，强调页面没有被任何插件 UI 打扰。

### ② 选中 → 深读（15s）
> 话术：读到一句想追问的话，选中它，旁边出现「深读」按钮。

演示：选中一句有主张的句子（如“AI 正在取代程序员的大部分工作”），点击「深读」。

### ③ 求真（30s）
> 话术：默认进入求真——这句话靠谱吗？不是简单给结论，而是给出支持程度、证据、以及“原文 vs 来源”对照。

演示：
- 支持程度徽章（充分支持 / 部分支持 / 证据不足 / 不支持 / 观点表达）
- 证据卡列表（来源类型 + 一句话结论 + 说明）
- 原文/来源对照块：原文说了什么、来源实际说了什么、差异在哪（如把“相关性”夸大为“因果”）
- 底部注明：未联网核验 / 已核验

### ④ 求深（20s）
> 话术：切换求深——这句话背后是什么？原理、相关概念、知识树。

演示：
- 原理平实解释
- 相关概念列表
- 知识树（root + 分支 + 节点）

### ⑤ 知识树节点 → 继续探索（15s）
> 话术：知识树不是装饰——点一个节点，它就成为新的深读对象，三连探索重新开始。

演示：点击知识树里的某个节点（如「大语言模型」），面板自动以该节点为新 Claim 重新分析。

### ⑥ 求异（20s）
> 话术：切到求异——还有没有不同看法？当前内容遗漏了什么？

演示：
- 当前观点概括
- 2~4 个立场卡（🟢乐观派 / 🟡谨慎派 / 🔴怀疑派，含论点+理由）
- ⚠️ 认知盲区（当前内容较少讨论的维度）

### ⑦ 连续深读（10s）
> 话术：回到网页再选一句，侧栏不用关，自动切换分析对象。

演示：回到网页选中另一句话 → 点击深读 → 面板自动更新为新 Claim 并重新分析。

## 常见问题应答

| 可能被问 | 回答要点 |
|---|---|
| 权限为什么需要 `<all_urls>`？ | 要让「深读」按钮在任意网页出现，content script 需要页面注入；插件只监听选择事件，不读取、不上传未选中的内容（最小权限 + 用户主动触发） |
| API Key 放哪？ | 项目根 `deepseek_api.key`，gitignored；运行时经 gen-config 注入 SW，不进前端代码 |
| 知乎能力怎么用？ | 经知乎开放平台 HTTP API（Bearer Access Secret）检索站内外内容，分析前注入上下文，结果可点击回原文；遵守配额（搜索 1000 次/天、直答 100 次/天）并做了缓存 |
| 判断一定对吗？ | 不制造虚假确定性：支持程度是“AI 基于检索与知识的评估”，非事实真值概率；观点类自动提示“无需溯源”；证据不足时明说不足 |

## 一句话收尾

> 你正在读的一句话，值得一次完整的深读——求真、求深、求异，从一个念头出发，探索整个世界。

# V2.0 演示段（信息溯源）

> 从「AI 判断真假」到「AI 帮你找到可追溯的证据」。

### ⑬ 智能选源（20s）
> 话术：V2.0 的求真不再让 AI 自由发挥——系统先判断声明需要什么类型的来源（政府文件？论文？媒体报道？），生成针对性关键词，经四级白名单过滤、按权威性排序后才检索。

演示：选中一条数据类声明 → 求真 → 展示来源列表的来源类型徽章（政府机构/学术论文/权威媒体…）与分组计数。

### ⑭ 读原文做证据比对（25s）
> 话术：搜索排名靠前≠证据。系统会真正打开来源网页读原文，逐源判断「支持 / 部分支持 / 不支持」，每条结论都附来源原文的**逐字引用**——杜绝 AI 编造。

演示：求真结果页的证据卡：结论徽章（五态之一）+ 逐字引用片段 + 可点击的原始 URL。

### ⑮ 五态诚实结论（15s）
> 话术：找不到可靠来源就明说"未找到"，部分符合就说"部分支持"——不硬凑答案。

演示：一条小众声明 → 「未找到可靠来源」；一条夸大表述 → 「部分支持」+ 差异说明。

### ⑯ 真实对立观点（30s）
> 话术：求异不再由 AI 编造"乐观派谨慎派"。系统检索真实资料、阅读原文、提取带 URL 的真实不同立场。

演示：争议声明 → 求异 → 每个观点卡：立场概括 + 逐字引用 + 来源链接；点击直达原文。

---

> 终极收尾金句：**不是"AI 帮你判断真假"，而是"AI 帮你从信息中找到可追溯的证据"。**

# V1.5 演示段（90 秒加映）

> 从「验证我指定的一句话」升级为「帮我发现文章中值得验证的每一句话」。

### ⑧ 悬浮球入口（15s）
> 话术：插件在页面右下角放了一个低干扰的「求」悬浮球——不打扰阅读，Idle 时不读取任何内容。

演示：正常滚动文章，指向右下角半透明悬浮球（hover 稍明显），强调点击前零采集。

### ⑨ 全文理解与声明发现（20s）
> 话术：点击悬浮球，插件理解全文结构，主动识别每一句值得验证的声明。

演示：点击悬浮球 → 旋转 Analyzing → Ready 后绿色徽标显示「16」个声明。强调：全文阶段**只发现+分类+定位，不批量验证**（隐私与配额红线）。

### ⑩ 本文概览（20s）
> 话术：侧栏打开「本文概览」——16 个可验证声明、4 个主观观点；每句带类型徽章（事实/数字/因果/比较/预测/定义）。

演示：概览统计行 + 声明列表；点击任意一句 → 进入现有求真/求深/求异工作台。

### ⑪ Hover 即问（25s）
> 话术：回到文章继续阅读，鼠标划过声明句——虚线下划线轻轻提示，悬浮卡出现「求真/求深/求异」。

演示：Hover 一句声明（如「π 约等于 3.14」）→ 黄色「可验证声明」提示卡 → 点「求真」→ 面板进入证据核验（支持程度徽章+证据卡）。再 Hover 一句普通过渡句——零反应（非声明零处理）。

### ⑫ 两种入口并存收尾（10s）
> 话术：悬浮球是「系统发现」，选区深读是「用户指定」——两条链路并存，互不打扰。

演示：快速回到选区深读（选中→深读→面板），强调 V1 流程完整保留。

> 收尾金句：**从"验证我指定的一句话"，到"帮我发现文章中值得验证的每一句话"。**
