# V3.0 升级要求 · 可视化动态交互

> 聚焦**功能与效果**的规划稿——先回答"用户会看到什么、感受到什么"，技术细节见各决策点备注。
> 版本定位：把「等一个黑箱结果」变成「看着系统替你求真」。

---

## 1. 痛点与机会

### 1.1 现状的三个问题

| # | 问题 | 用户体感 | 根因（简） |
|---|---|---|---|
| P1 | **算法黑箱** | 点「求真」后只有一句话进度在"假装推进"，不知道系统在干什么、进行到哪一步、是否卡住 | loading 为定时器伪造节奏，与真实管线脱节 |
| P2 | **单次等待过长** | 一次分析 10~30s，期间画面几乎静止，用户只能干等，无法中途干预 | 全链路跑完才一次性返回；中间结果不上屏 |
| P3 | **深度不可见** | 做完的深度（递归溯源到源头、八维评分、证据绑定、数字核对）只在文字里，用户感知不到"它真的追到了源头" | V2.9 结构数据丰富但 UI 只出最终文本列表 |

### 1.2 机会

V2.9 管线其实已经是一套**可以讲成故事**的过程：

```
定目标 → 多路检索 → 筛出可信来源 → 追到源头 → 抽取数字 → 逐条核对 → 绑定结论
```

每一步都有真实、可展示的结构数据（策略、引擎、来源、簇、上游链、数值、绑定状态）。
V3.0 要做的不是造新算法，而是**把这套过程变成用户看得见、跟得上的视觉叙事**——
这正是"求真"产品区别于"AI 问答盒子"的核心体验，也是黑客松评审最容易被记住的部分。

---

## 2. 体验目标（北极星）

> **用户能在 3 秒内看懂"系统正在做什么"，能在任意时刻知道"还要等多久/到哪一步了"，并在完成后直观看到"它凭什么下这个结论"。**

三条体验线支撑：

1. **实时工作流剧场**（Live Pipeline）：loading 从"假进度"变成"真直播"
2. **渐进式产出**（Progressive Output）：不等全部完成，边跑边出内容
3. **结论的证据网络**（Evidence Network）：结果页从"文字列表"升级为"可读的证据图"

---

## 3. 方案总览（效果视角）

### 3.1 实时工作流剧场 —— "看着它替你求真"

把整个验证过程渲染成一条**流动的管线动画**，每个阶段真实推进：

**用户会看到（求真模式示例）：**

```text
┌─────────────────────────────────────────────┐
│  求真直播                                    │
│                                             │
│  ① 理解目标        ✓ 完成（0.8s）            │
│     "深圳校服采购价上涨 35%"                  │
│     → 事实声明 · 需政府/媒体来源 · 动态数据    │
│                                             │
│  ② 双路检索        ● 进行中（2.3s）          │
│     ┌─ Exa 语义      ⟳ 3/10 结果             │
│     └─ metaso 广泛   ⟳ 5/10 结果             │
│                                             │
│  ③ 筛选来源        ○ 等待                    │
│  ④ 递归溯源        ○ 等待                    │
│  ⑤ 数字核对        ○ 等待                    │
│  ⑥ 绑定结论        ○ 等待                    │
└─────────────────────────────────────────────┘
```

**关键交互：**

| 功能 | 效果 |
|---|---|
| 真实进度上报 | 每一阶段完成/失败/超时都有真实信号，不再是定时器演戏 |
| 阶段图标动效 | 完成打钩弹出、进行中光点流动、失败变红可点看原因 |
| 引擎级细节 | 检索阶段显示"哪个引擎、搜到什么、几条有效"，一眼知道双通道是否降级 |
| 点击展开 | 想看细节点一下：该阶段用了什么 Query、命中哪些域名、去重后剩几条 |
| 可中途干预 | 长时间无进展时出现「仍在努力/重新生成/取消」——不再无限干等 |
| 保持简洁 | 默认只显示 6 个主阶段（可折叠）；细节默认收起，绝不信息过载 |

**效果意图**：用户第一次看会觉得"它真的在查"；第三次用会形成信任——"我看到它追到统计局官网了，所以我相信这个结论"。

### 3.2 渐进式产出 —— "先给骨架，再长血肉"

不等全链路结束才出结果，改为**分片到达**：

| 阶段 | 用户已能看到 |
|---|---|
| 检索完成时 | 「已找到 N 个候选来源」清单先上屏（标题+域名+类型），灰态占位 |
| 读取完成时 | 逐条填充摘要/关键句，来源卡逐个"点亮" |
| 核对完成时 | 每条证据的状态徽章逐个出现（支持/矛盾/无关） |
| 结论就绪时 | 顶部结论卡淡入，证据网络图生成 |

**效果意图**：用户感受到"系统一直在动、一直在给我东西"，而不是"转圈 20 秒后啪一下全出来"。即便最后结论需要久等，前面每一秒都有新信息到达，P2 的等待焦虑被大幅稀释。

### 3.3 证据网络 —— "结论凭什么，一眼看懂"

结果页在保留现有来源卡的基础上，增加**证据关系图视图**：

**用户会看到：**

```text
        ┌──────────────┐
        │  我的结论       │  Supported ✓（partial→升 supported 因数字核对通过）
        │  涨了 35%       │
        └──────┬───────┘
               │ 绑定
     ┌─────────┼──────────┬──────────────┐
     ▼         ▼          ▼              ▼
┌────────┐ ┌────────┐ ┌────────┐   ┌──────────┐
│ 深圳教育局 │ │ 南方都市报 │ │ 深圳政府网 │   │ 知乎讨论  │
│ 一手·官方 │ │ 转载自教育局│ │ 原发通报   │   │ 社区·低权威 │
│ 数字✓35% │ │ 数字✓35% │ │ 数字✓35% │   │ 无数字    │
└────┬───┘ └───┬────┘ └───┬───┘   └──────────┘
     └─溯源─────┴──────▲──┘
                       │ 共同上游
                  （都指向政府通报原文）
```

**能力拆解：**

| 视图能力 | 效果 |
|---|---|
| 结论 → 证据绑定线 | 结论引用哪些来源，连线即见；数字绑定（35% 在证据中是否真实存在）以✓/✗标出 |
| 溯源树 | 点「政府通报」节点向上展开：谁转载了它、谁是源头——递归溯源结果直接可视化 |
| 类型分层 | 一手/转载/社区/官方用色块与连线粗细区分，权威≠一手一眼看懂 |
| 矛盾证据 | 支持结论的证据绿色系、矛盾的红色系并排，诚实展示不同观点 |
| 可交互 | 悬停节点高亮相关证据、点击进入该来源的完整判定详情 |
| 无网也可读 | 自动布局成纵向流（手机/窄栏可读），图只是"增强视图"，不替代文字结论 |

**效果意图**：这是"深读"与"AI 摘要"拉开差距的地方——用户不只是拿到一个结论，而是拿到一张**可以检查的证据地图**。评审现场演示时，"点开溯源树追到官方通报原文"会成为记忆点。

### 3.4 反馈节奏优化（贯穿以上所有）

| 时机 | 反馈 |
|---|---|
| < 1.5s | 立即显示直播剧场骨架（不给白屏） |
| 每阶段完成 | 打钩 + 平滑过渡（300ms 内） |
| 单阶段 > 8s | 该阶段节点脉冲提示「较慢，仍在尝试」 |
| 单阶段 > 20s | 给出选项：继续等 / 用已得结果先出结论 / 取消 |
| 失败 | 具体到阶段与原因（"metaso 限流"≠"分析失败"） |
| 缓存命中 | 显示「秒回（缓存）」，不播动画——尊重用户时间 |

## 4. 视觉与动效规范（延续既有 Liquid Glass 语言）

不推翻现有设计系统，在其上建立"动态层"：

- **语言**：毛玻璃卡片 + 两档圆角（沿用现有）——让动效长在既有骨架上，用户不觉突兀
- **主色**：延续信纸黄基准 + 玻璃白；新增一套**语义动效色**：完成=暖金✓、进行中=呼吸光点、失败=柔和红、缓存=灰
- **运动**：全部缓入缓出；推进动画 ~300ms、节点点亮 ~200ms、淡入 ~150ms；不搞弹跳/回弹等花哨
- **图形叙事优先**：管线用"光点沿路径流动"而非"进度条转圈"——流动方向即工作顺序，用户自然读懂 workflow
- **尊重深色/浅色**：两种模式都验证动效对比度
- **降级尊重**：`prefers-reduced-motion` 时全部动画关闭，仅保留状态色块切换（可访问性底线）
- **性能纪律**：动画只作用于 transform/opacity（不触发重排），滚动时暂停装饰动画

## 5. MVP 范围建议

**M0（必须，解决 P1+P2 大部分）**
- 真实管线阶段上报（后台给信号，UI 不再演戏）
- 直播剧场：6 主阶段 + 引擎级细节（可折叠）+ 完成/失败/缓存状态
- 渐进式产出：候选来源清单先上屏 → 逐条点亮

**M1（必须，解决 P3 + 黑客松记忆点）**
- 证据网络图：结论绑定线 + 一手/转载分层 + 溯源树展开 + 矛盾并排
- 数字绑定 ✓/✗ 可视化

**M2（体验加分，时间够再做）**
- 引擎级动画细化（检索中的流动光点、来源逐个"被找到"的连线动画）
- 阶段超时干预（继续/先出结论/取消）
- 求深/求异模式轻量适配（同一视觉语言，步骤更少）

**明确不做（V3.0 边界）**
- 不重做算法、不改结论逻辑——只把已有过程/结果"翻译"成视觉
- 不做 3D/炫技动效；不做独立"分析回放"页面（先做面板内嵌）

## 6. 请拍板的决策点

| # | 问题 | 建议 | 备注 |
|---|---|---|---|
| V1 | 直播剧场默认展开到多细？ | 6 主阶段常显、细节默认收起 | 展开=信息过载风险 |
| V2 | 证据网络图以什么为主视图？ | 结果页顶部「结论卡 + 关系图」并排，来源卡列表保留在下可切换 | 窄栏时图自动变纵向 |
| V3 | 渐进式产出做到多深？ | M0 先做"候选清单先上屏"，逐条判定点亮 | 全文流式是另一工程量级 |
| V4 | 求深/求异模式是否同步改造？ | 仅 M2 轻量适配 | 三模式视觉统一性 vs 工作量 |
| V5 | 是否需要"引擎是否降级/无凭证"的可视提示？ | 需要（检索节点直接显示降级徽标） | 与诚实降级原则一致 |

---

## 7. 一句话总结

> **V3.0 不新增"分析能力"，新增"被看见的分析过程"——把 V2.9 已经做到的深度，用动态可视化讲给用户听，让等待变成信任，让结论变成可检查的证据地图。**
