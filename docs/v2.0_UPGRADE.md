# 「求真」V2.0 升级要求

> 基于 V1.6 已完成的知乎 API + 联网搜索能力进行升级。
>
> **核心目标：从“AI 判断文本是否需要验证”升级为“信息对象识别 → 信源发现 → 证据验证”的信息溯源系统。**
>
> 保留现有 Chrome Extension、悬浮球、全文扫描、Side Panel、求真/求深/求异及搜索能力，不推翻已有产品闭环。

---

# 1. 核心流程升级

V1.6：

```text
文本
↓
是否需要验证
↓
声明
↓
搜索
↓
验证
````

V2.0：

```text
网页内容
↓
信息对象识别
↓
验证价值判断
↓
核心声明提取
↓
来源类型判断
↓
生成搜索关键词
↓
Search Controller
↓
白名单 / 来源优先级
↓
Search API
↓
候选来源
↓
来源排序
↓
Web Reader
↓
阅读原文
↓
声明 ↔ 证据验证
↓
结论 + 证据 + 原始来源
```

---

# 2. 信息对象识别

不再首先判断“主观 / 客观”。

优先识别当前内容属于什么信息对象，例如：

```text
普通正文
事实陈述
数据 / 数字
研究报告 / 文件
论文
政府文件
机构信息
媒体报道
人物 / 事件
观点 / 判断
修辞 / 无意义文本
```

信息对象识别结果决定后续处理方式。

例如：

```text
“中泰证券-长安汽车-xxx.pdf”
↓
研究报告
↓
提取机构 / 标题 / 日期 / 类型
↓
进入信源识别
```

而不是：

```text
“经营质量向上”
↓
观点
↓
无需验证
```

---

# 3. 验证价值判断

将：

> “是否需要验证”

重新定义为：

> **“该信息是否具有外部验证 / 溯源价值？”**

重点识别：

* 可外部验证的事实；
* 数据；
* 人物经历；
* 时间、地点、事件；
* 论文 / 报告 / 文件；
* 机构发布的信息；
* 具有明确来源的观点。

过滤：

* 夸张性修辞；
* 无外部事实意义的数字；
* 单纯情绪表达；
* 无信息价值的文本。

自动扫描模式：

> **优先展示可追溯信息，不主动展示普通个人观点。**

---

# 4. Claim 与上下文

Claim 不再只使用当前句子。

分析时应结合：

```text
当前句
+
前后文
+
所属段落
+
必要时所属章节
```

目的：

> 防止一句话看似是观点，但上下文中存在能够验证该观点的事实声明。

Claim 数据至少包含：

```javascript
{
  id,
  text,
  context,
  type,
  verifiable,
  objectType,
  sourceRequirement
}
```

---

# 5. 来源类型识别

建立统一 Source Type：

```text
政府机构
科研机构
学术论文
官方组织
权威媒体
专业媒体
商业机构
证券机构
企业官方来源
知乎
其他
```

来源类型必须影响：

* 权威性评分；
* 搜索优先级；
* 最终展示。

例如：

```text
德国政府
≠ 专业媒体

平安证券研究报告
≠ 个人观点
```

---

# 6. Search Controller

搜索不再直接交给 AI 自由决定。

流程：

```text
Claim
↓
判断需要什么类型的来源
↓
生成搜索关键词
↓
读取来源白名单
↓
确定搜索优先级
↓
Search API
```

来源白名单应支持：

```text
优先来源
允许来源
低优先级来源
禁止来源
```

---

# 7. 来源排序

候选 URL 返回后，由 DeepSeek 综合判断：

```text
来源类型
+
机构权威性
+
与 Claim 的相关性
+
来源时间
+
原始程度
```

进行排序。

原则：

> **优先原始来源，而不是优先搜索排名靠前的网页。**

---

# 8. Web Reader 与证据验证

排序后的 URL 才进入 Web Reader。

流程：

```text
URL
↓
读取原文
↓
提取相关内容
↓
判断是否支持 Claim
↓
提取具体证据
```

必须区分：

```text
来源存在
≠
来源相关
≠
来源支持 Claim
```

最终结果至少包含：

```text
结论
证据
原始 URL
来源类型
```

---

# 9. 验证结果状态

严格区分：

### 无需验证

> 系统判断该内容没有明确的外部验证需求。

### 找不到可靠来源

> 该内容具有验证价值，但当前没有找到足够可靠的来源。

### 找到来源但不支持

> 找到了相关来源，但来源不能支持原文声明。

### 部分支持

> 来源支持部分内容，但原文存在扩大、简化或推断。

### 支持

> 找到可靠来源，并能够支持核心声明。

不得混用以上状态。

---

# 10. 求异升级

“求异”不再由 AI 自行生成抽象观点。

必须优先：

```text
原 Claim
↓
搜索不同立场 / 不同结论的真实资料
↓
读取来源
↓
提取不同观点
↓
提供来源 URL
```

输出：

```text
观点
来源
核心依据
```

如果没有可靠的不同观点：

> 明确告知用户“暂未找到可靠的不同观点”。

**禁止用 AI 自行编造“乐观派 / 谨慎派 / 怀疑派”等观点作为事实存在的替代。**

---

# 11. 自动扫描与主动询问分离

## 自动扫描

目标：

> **快速发现值得溯源的信息。**

重点：

```text
事实
数据
报告
论文
政府文件
媒体报道
人物经历
事件
```

减少：

```text
普通观点
情绪
修辞
无意义数字
```

---

## 主动询问

用户主动选中文本后：

> 可以进行更深入的语义判断。

允许分析：

```text
事实
观点
推测
修辞
因果关系
逻辑关系
上下文
```

两种模式不得简单复用同一套判断逻辑。

# 12. UI / UX 修正

### 来源

所有最终来源必须：

> **可直接点击原始 URL。**

---

### Claim 定位

用户点击声明后：

```text
Side Panel Claim
↓
网页对应句段
↓
自动定位 / 高亮
```

---

### 悬浮球

增加：

* 自由拖动；
* 限制在可视区域；
* 记忆上次位置。

同时降低视觉侵入：

* 适当缩小尺寸；
* 降低阴影；
* 优化透明度；
* 减少对正文的遮挡。

---

# 13. 验收标准

### 信息识别

* [ ] 能识别研究报告 / 文件等信息对象
* [ ] 能区分政府机构、媒体、科研机构、商业机构等来源
* [ ] 能过滤明显无验证价值的修辞和数字

### Claim

* [ ] 分析 Claim 时考虑上下文
* [ ] 能发现观点背后的可验证信息
* [ ] Claim 能定位回网页原文

### 搜索

* [ ] 根据 Claim 类型选择来源
* [ ] Search Controller 执行来源白名单
* [ ] 候选来源能够排序
* [ ] Web Reader 能读取原文
* [ ] 能判断来源是否真正支持 Claim

### 结果

* [ ] 来源提供可点击 URL
* [ ] 明确区分“无需验证 / 未找到来源 / 不支持 / 部分支持 / 支持”
* [ ] 求异观点具有真实来源

### 回归

* [ ] V1.6 知乎 API 正常
* [ ] 联网搜索正常
* [ ] 原有选区深读正常
* [ ] 求真 / 求深 / 求异正常
* [ ] 悬浮球正常

---

# 14. V2.0 完成标志

一次完整 Demo 应能够：

```text
打开知乎文章
↓
点击「求真」
↓
系统识别文章中的重要信息对象
↓
提取值得验证的 Claim
↓
判断所需来源类型
↓
搜索并筛选可靠来源
↓
读取原始网页
↓
判断来源是否真正支持 Claim
↓
展示：
结论 + 证据 + 来源 URL
↓
用户点击 Claim
↓
网页定位到原文
```

最终产品定位：

> **不是“AI 帮你判断真假”，而是“AI 帮你从信息中找到可追溯的证据”。**
