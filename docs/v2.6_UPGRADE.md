# 1. 轮次 A：检索系统改造（search_advise.md 落地）

## 1.1 架构变化：从"硬路由"到"双核普遍召回"

```text
改造前：questionType → 决定搜索引擎（fact 排除 Exa → 召回盲区）
改造后：所有问题类型 = Exa + Metaso 双核召回 + Zhihu 低配额补充；
        questionType 只影响各引擎预算配额（不再排除任何引擎）
```

引擎预算表（`v25-pipeline.js` `ENGINE_BUDGET`）：

```text
fact:     Exa 4 / Metaso 4 / Zhihu 1
academic: Exa 5 / Metaso 3 / Zhihu 1
policy:   Exa 3 / Metaso 5 / Zhihu 1
event:    Exa 5 / Metaso 4 / Zhihu 1
data:     Exa 4 / Metaso 4 / Zhihu 1
open:     Exa 4 / Metaso 4 / Zhihu 2
```

### `src/core/ai/source-analyzer.js`

### `src/core/ai/source-registry.js`
- verified 扩充：stats.gov.cn、npc.gov.cn、court.gov.cn、spp.gov.cn、esa.int、fda.gov、europa.eu、cdc.gov、nih.gov、nasa.gov、whitehouse.gov 等；
- `mp.weixin.qq.com`、`weibo.com` → candidate（不预设高权威）。

### `src/core/ai/scoring-engine.js`（改动最大）
六维 → **八维综合评分**：

```text
FinalScore = Σ(维度 × 权重) + prefBonus + firstPartyBonus + targetPaperBonus − syndPenalty

authority    0.25   registry 先验 与 类型先验 取大（gov=95…media=70…other=45）
relevance    0.20   中 + 英关键词命中率（keywordsEn 参与，英文官方页不再被中文关键词误伤）
directness   0.15   是否直接回答当前问题（关键词/聚焦短语/数字/实体官方域 +30）
entity       0.12   来源主体 = 问题主体？（实体名命中或官方域直中）
scope        0.08   地域范围匹配（全国 vs 县级 = 20 分重罚）
temporal     0.06   问题年份 vs 来源年份（防 2023 报告顶替 2025 数据）
originality  0.08   original=95 / secondary=45 / tertiary=20
evidence     0.06   摘要启发式（百分号/万亿/官方文件词根）

preferredSources 命中 +8（此前是无效字段，现真正进入评分）
firstPartyBonus  原始发布 + 官方/学术/论文 +5
targetPaperBonus 确认是目标论文 +6（轮次 B 加入）
转载惩罚         suspectedSyndication −6；同簇非代表再 ×0.75
```

### `src/core/ai/evidence-graph.js`
- 转载检测从单一阈值改为**三级分级**：
  - `duplicate`：标题 ≥0.82 且摘要 ≥0.72
  - `likely_syndication`：标题 ≥0.70，或（标题 ≥0.40 且摘要 ≥0.60，抓"改标题转载"）
  - `possible_syndication`：标题 ≥0.40 且摘要 ≥0.40（只标记不并入簇，防误杀）
- `independentCount` 显式化：**网页数量 ≠ 独立证据数量**。

### `src/core/ai/verify-engine.js`
- 新增 `selectDiverseTopN`：Top-6 多样性验证池（同来源类型最多占一半；轮次 B 再叠加同溯源簇限额）。

### `src/core/ai/analyzer.js`
- truth 提示词强制证据绑定：只能依据【溯源检索结果】作答，`evidences[].evidenceId` 必须引用 E1~E5 编号；
- 硬降级校验：检索无来源 → supported/partial 自动降级 insufficient；有来源但未绑定编号 → 降级 partial。

# 2. 轮次 B：Evidence Targeting & Provenance Tracing（upgrade.md 落地）

## 2.1 新增模块

### `src/core/ai/evidence-target.js`（前置决策层，P0）
搜索前回答"找什么"：

```text
Claim + Context → 显式来源提取（URL/DOI/arXiv/PMID）
                → Claim 分类（11 类：PERSON/PERSON_EVENT/EVENT/PRODUCT/COMPANY/POLICY/
                  STATISTICS/ACADEMIC/ORIGINAL_REPORT/OFFICIAL_DOCUMENT/DATASET）
                → Evidence Target（EXACT_ENTITY/ENTITY_EVENT/EXACT_PAPER/…9 类）
                → Search Strategy（EXACT_SOURCE/PREFERRED_SOURCE/IDENTIFIER_SEARCH/…6 类）
                → Entity–Event 解析状态（RESOLVED / AMBIGUOUS / UNRESOLVED）
```

- 匿名人物（"朱女士"）→ `AMBIGUOUS`，**禁止强行绑定身份**（§32 Ambiguity Policy）；
- 1 次 DeepSeek 调用（失败/无凭证 → 全规则兜底，零依赖可用）；
- `buildBinding()` + 6 项硬校验（声明明确/有候选/证据支持/显式来源已用/学术目标确认/实体解析），输出 `bindingStatus/target/ambiguity/hardValidation`。

### `src/core/ai/academic.js`（Academic Exact-Source，P0/P2）
- `buildTarget`：DOI/arXiv/PMID/URL + 《论文标题》 + 超链接锚文本；
- `validatePaper` 匹配优先级：

```text
DOI 精确命中 > arXiv/PMID 精确 > 显式 URL 直中（EXPLICIT_URL）> 标题精确 > 标题近精确(dice≥0.85)
  → TARGET_PAPER
语义相似（0.5≤dice<0.85）→ 只能标 RELATED_PAPER（禁止把"相关论文"当"目标论文"）
```

### `src/core/ai/provenance.js`（溯源层，P1）
- `extractProvenance`：规则式提取上游线索——"据X报道/援引X"（EXPLICIT_CITATION）、"转载自/编译自"（REPOST）、according to/reported by（QUOTED_SOURCE）、原始采访（INTERVIEW）、`Source: http…`（EXPLICIT_LINK）；
- `buildGraph`：共同上游检测 → `provenanceClusterId + independence（SHARED_UPSTREAM/INDEPENDENT/DERIVED）`；
- `trace`：受控上游检索（maxUpstreamCandidates=3 / maxPageReads=3 / maxAdditionalSearches=3）；
- `confidenceFor`：HIGH（显式链接+引用）/ MEDIUM / LOW（仅推断，不得称首发）。

## 2.2 集成改动

### `src/core/ai/v25-pipeline.js`
新主流程：

```text
Claim
 ├─ 并行：Query Analyzer（策略） / Evidence Target（目标） / 页面抓取（上下文，轮次 C）
 ↓
buildPlan（显式来源步最优先 → 双核 → 官方域定向步）
 ↓
检索 → URL 去重 → Registry → Source Analysis
 ↓
Academic Exact-Source 验证（claimType=ACADEMIC → 全候选 validatePaper）

Evidence Clusters → 八维评分

Provenance Tracing（媒体/二手候选，预算受控）→ 共同上游检测

Top-6 多样性验证池（同溯源簇只留 1 个代表）→ Web Reader → 逐源判定 → 五态结论

Binding + Hard Validation → 输出 evidenceTarget / binding / provenance / stats
```

输出新增字段：

```js

v.binding          // { bindingStatus, target, entityResolutionStatus, directSourceAvailable/Used, paperStatus, hardValidation, ambiguity }
v.provenance       // { traced, upstreamHits, stops, clusters, confidence }
stats              // 新增 independentCount / sharedUpstreamCount
```

# 3. 轮次 C：知乎超链接论文引用修复

## 3.1 问题

- 现象：在知乎文章选中引用论文的句子，模型返回的是"其它论文"，而不是文章实际引用的论文；
- 根因 1：上下文只有选中句文本，从未抓取文章页 HTML；
- 根因 2：`web-reader.js` 的 `htmlToText()` 会把 `<a href="...">` 的 **href 属性整个丢弃**（只留可见文字），超链接形式的论文链接永远无法被提取。

## 3.2 修复

### `src/core/ai/web-reader.js`
- 新增 `extractLinks(html)`：在剥离标签**之前**从 `<a>` 提取 `{href, 锚文本}`（去重、上限 50）；
- `readUrl(url, opts)` 支持 `opts.wantHtml` 返回原始 HTML（默认不返回，控内存）。

### `src/core/ai/evidence-target.js`
- 新增 `classifyLink(href)`：链接分类 DOI / arXiv / PMID / URL；
- 新增 `extractExplicitSourcesFromHtml(html)`：从页面锚点提取显式来源（**锚文本即论文标题提示**）；过滤站内导航/社交/搜索噪声链接（zhihu.com/question、baidu、weibo 等）；
- 新增 `mergeExplicitSources(et, pageText, htmlLinkSources)`：页面级来源并入 evidenceTarget（去重，任一命中 → `directSourceAvailable=true`）。

### `src/core/ai/v25-pipeline.js`
- 新增 `fetchPageContext(url)`：**与 LLM 分析并行**抓取文章页（页面级缓存：10 条 / 10 分钟；失败静默降级）；
- 抓取结果并入 evidenceTarget → `buildPlan` 自动把论文链接排成**最优先的 explicit 步**（直读原文，不先做语义搜索）。

### `src/core/ai/academic.js`
- `buildTarget`：锚文本作为论文标题线索；
- `validatePaper`：新增 `EXPLICIT_URL` 直中判定（页面直接给出的原文链接 = TARGET_PAPER）。

## 3.3 修复后链路（针对知乎文章）

```text
选中句子 → 并行抓取文章页 HTML
  → extractLinks 拿到 <a href="doi.org/...">论文标题</a>
  → classifyLink → DOI + 锚文本标题 → 并入显式来源
  → explicit 步最先执行：直读 doi.org 原文
  → validatePaper：DOI 命中 → TARGET_PAPER（面板"目标论文"徽章、评分 +6）
  → 其他语义命中的论文 → RELATED_PAPER（不冒充目标论文）
  → Hard Validation 的 academic_target 检查通过
```

# 5. 行为变化汇总

| 场景 | V2.5（改造前） | V2.6（改造后） |
|---|---|---|
| NASA 类问题 | fact 排除 Exa，只有中文关键词，官方源召回不到 | 双核 + 英文 Query + site:nasa.gov 定向，官方页评分优先 |
| 全国人口 vs 县级 | 无地域维度，县级报告可能顶替 | scope 维度重罚（20 分） |
| 公众号"健康管理学会" | 可能被误判为政府 | 按发布主体判 identityType，学会→org |
| 民法典颁布时间 | 地方检察院案例可能排前 | directness + scope + originality 综合，全国人大文本优先 |
| 匿名人物"朱女士" | 只搜名字、可能强行绑定 | PERSON_EVENT + AMBIGUOUS，禁止断言身份 |
| 论文引用 | 重新语义搜索，可能把"相关论文"当目标 | 超链接/DOI 直读验证，TARGET_PAPER vs RELATED_PAPER 严格区分 |
| 多家媒体转同一通讯社 | 按独立证据计数 | 共同上游检测 → 同簇只留代表，独立来源数如实统计 |
| 最终结论 | 有证据绑定 | 6 项硬校验 + AMBIGUOUS 保守提示 |

# 6. 已知遗留

1. **Entity–Event Resolution 完整版**（upgrade.md §8.3–8.4 多候选事件逐一检索比对）未实现——当前为单次决策状态机（RESOLVED/AMBIGUOUS/UNRESOLVED）；
2. **Provenance 纳入评分的完整化**（§27 P2）：TARGET_PAPER 加分已接入，但 Provenance Bonus（上游加分）仅以独立性标记/统计呈现，未改八维权重；
3. **preferredSources 完全路由化**（§37 P2）：已用于显式来源步与官方域步，未对每种 claimType 做专属检索步（如 PRODUCT→官方产品页域名库）；
4. `trace()` 上游定向搜索走 metaso；Exa 的 includeDomains 上游追踪未启用；
5. LLM 版 Evidence Target 分析（1 次调用）未在真实 API 下联调，冒烟测试只覆盖规则兜底路径；
6. 知乎等页面若被反爬拦截（`fetch_failed`），页面超链接提取会静默回退到语义搜索——可加 content-script 侧兜底（把选中句所在段落的 `<a>` 链接一并上报）。
