# 「求真」V2.5 升级要求

> 基于 V2.0 的 Claim 验证流程，进一步升级来源检索与评价能力。
>
> **核心目标：从“找到可靠来源”升级为“系统地发现、识别、比较可靠来源”。**
>
> 保留现有 Extension、全文分析、Claim、求真/求深/求异及 Web Reader，不推翻已有流程。

---

# 1. 搜索流程升级

新增 Query Analyzer：

```text
Claim
↓
Query Analyzer
↓
判断问题类型
↓
确定搜索策略
↓
搜索
````

根据问题类型决定：

* 搜索关键词；
* 来源类型；
* 时间要求；
* 搜索预算；
* 是否需要双搜索引擎。

例如：

```text
事实查询 → 官方来源优先
学术问题 → 论文 / 研究机构优先
政策问题 → 政府 / 监管机构优先
开放研究 → 双搜索引擎
```

---

# 2. 双搜索引擎召回

接入：

```text
metaso Search : base url: "https://metaso.cn/search-api/playground"(不确定)，api_key: `metaso_api.key`
+
Exa : base url: "https://api.exa.ai/search", api_key: `exa_api.key`
```

职责区分：

```text
metaso
→ 广泛召回

Exa
→ 语义召回
```

不要求每次固定调用两个搜索引擎。

由 Query Analyzer 根据问题复杂度决定搜索预算。

---

# 3. URL 合并与去重

多个搜索源返回结果后统一处理：

```text
Search Results
↓
URL Normalize
↓
Canonical URL
↓
去除 Tracking 参数
↓
URL Deduplication
↓
Unique URL Set
```

需要处理：

* tracking parameters
* URL fragment
* http / https
* www / non-www
* canonical URL
* 重定向

---

# 4. Trusted Source Registry

将原有简单白名单升级为：

> **Trusted Source Registry（可信来源注册表）**

至少支持：

```text
Verified
Candidate
Restricted
```

### Verified

已经确认的可信来源。

### Candidate

系统发现但尚未充分确认的新来源。

### Restricted

低质量、垃圾、聚合或存在明显风险的来源。

---

## 核心原则

未知来源：

```text
不直接删除
↓
进入候选池
↓
进行来源分析
↓
获得临时评价
```

Registry 提供的是：

> **来源先验，而不是绝对准入规则。**

---

# 5. 来源分析

对候选网页进行基础分析：

```text
URL
Title
Author
Organization
Published Date
Canonical URL
Page Content
```

识别：

```text
来源类型
一手 / 二手 / 三手
所属机构
专业领域
引用来源
```

来源类型至少包括：

```text
政府机构
科研机构
学术论文
官方组织
权威媒体
专业媒体
企业官方来源
商业机构
知乎
其他
```

---

# 6. 可信度与一手性分离

不得将：

> **Authority**

与：

> **Originality**

视为同一个指标。

例如：

```text
高权威媒体
≠
一手来源
```

来源评价至少区分：

```text
Authority
Expertise
Relevance
Originality
Evidence
Freshness
```

---

# 7. 来源排序

采用：

```text
候选来源
↓
硬过滤
↓
来源分类
↓
结构化来源分析
↓
综合评分
↓
最终排序
```

优先过滤：

* 明显恶意页面；
* 无法访问页面；
* 完全不相关页面；
* 明显垃圾内容。

然后再进行评分。

---

# 8. LLM 与评分器职责分离

不得采用：

```text
URL
↓
LLM
↓
可信度 93
```

应采用：

```text
URL
↓
规则 / Registry
↓
LLM 来源分析
↓
结构化判断
↓
Scoring Engine
↓
最终排序
```

LLM 负责：

> **理解来源。**

评分器负责：

> **综合来源信息并进行稳定排序。**

---

# 9. 证据独立性

同一事实可能被多个网页转载。

因此：

```text
多个 URL
↓
识别引用关系
↓
判断是否来自同一原始来源
```

避免：

> **把多个转载页面误认为多个独立证据。**

V2.5 至少支持基础的：

```text
Source A
  ↓ cites
Source B
```

关系记录。

完整 Source Graph 暂不要求实现。

---

# 10. 求真结果升级

求真最终展示：

```text
结论
↓
证据
↓
来源
↓
来源类型
↓
原始 URL
```

来源必须：

> **可点击、可追溯。**

同时明确区分：

```text
无需验证
未找到可靠来源
来源不支持声明
部分支持
支持
```

不得混淆。

---

# 11. 性能与成本

搜索策略采用动态预算。

简单问题：

```text
优先单路搜索
```

复杂问题：

```text
metaso + Exa
```

缓存：

```text
Query
URL
Source Analysis
```

尽量避免重复搜索和重复来源分析。

---

# 12. 本阶段不做

以下能力作为后续架构预留，不纳入 V2.5 验收：

* ❌ 完整 Source Graph
* ❌ 自动学习来源权重
* ❌ 自动修改 Trusted Source Registry
* ❌ LLM Critic
* ❌ 用户个性化来源偏好
* ❌ 复杂机器学习排序模型

---

# 13. 验收标准

### 搜索

* [ ] Query Analyzer 能判断基本问题类型
* [ ] metaso / Exa 能按策略调用
* [ ] 多来源搜索结果能够合并
* [ ] URL 能规范化并去重

### 来源

* [ ] Trusted Source Registry 正常工作
* [ ] 支持 Verified / Candidate / Restricted
* [ ] 能识别基本来源类型
* [ ] 能区分一手 / 二手来源
* [ ] Authority 与 Originality 分离

### 证据

* [ ] 能识别基础引用关系
* [ ] 能避免明显的重复转载被当作独立证据
* [ ] 求真结果提供可点击原始 URL
* [ ] 能区分“无来源”和“无需验证”

### 回归

* [ ] V2.0 Claim 分析正常
* [ ] 求真正常
* [ ] 求深正常
* [ ] 求异正常
* [ ] Web Reader 正常
* [ ] 原有 Extension 交互正常

# 14. V2.5 完成标志

完整链路：

```text
Claim
↓
Query Analyzer
↓
metaso / Exa
↓
URL 合并去重
↓
Trusted Source Registry
↓
来源分析
↓
一手 / 二手识别
↓
证据关系分析
↓
综合评分
↓
来源排序
↓
Web Reader
↓
Claim ↔ Evidence
↓
结论 + 证据 + 原始来源
```

最终能力：

> **不仅告诉用户“找到了什么”，还告诉用户“为什么这个来源值得相信，以及它是不是原始证据”。**

````
