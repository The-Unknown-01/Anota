# 求真 · 深读

> 在正在阅读的网页上，选中一句话：**验证它、理解它，并发现你可能遗漏的观点。**

「求真 · 深读」是一个 Chrome Manifest V3 扩展。它将阅读中的一句 Claim 带入侧栏，通过三种模式提供结构化分析：

- **求真**：这句话靠谱吗？——检索、读原文、溯源并把结论绑定到证据。
- **求深**：背后是什么？——解释原理、概念和知识关系，并仅把公开知乎回答作为辅助材料。
- **求异**：还有别的看法吗？——从公开知乎回答中寻找有出处的反例、补充视角或不同立场；没有可靠来源就明确说明。

当前分支：`v3.1-oauth-only`。

## 当前版本重点

### OAuth-only 登录门禁

代理分发模式不再使用邀请码或静态访问令牌。用户必须亲自完成知乎官方 OAuth 授权，扩展才可调用受保护的分析与检索代理 API。

```text
扩展 Side Panel
  → 请求 Worker /auth/zhihu/start
  → 新标签打开知乎官方授权页（由用户本人确认）
  → Worker /auth/zhihu/callback 换取 OAuth Token
  → Worker 将授权 flow 标为 authorized
  → 扩展短轮询 /auth/zhihu/status?flow_id=...
  → 一次性领取本项目应用会话 JWT
  → 已登录后调用分析/检索代理
```

安全边界：

- **知乎 OAuth Token 只保留在 Worker 服务端会话中，绝不下发到扩展。**
- 扩展只保存 Worker 签发的短期应用会话 JWT，且该 JWT 必须带有 `auth=zhihu_oauth`。
- OAuth `app_key`、开放平台 Access Secret、DeepSeek / Exa / metaso 等密钥只应存放在 Cloudflare Worker Secrets 或本地开发凭证文件中，不写入扩展包、git、日志或 README。
- 代理模式中，未完成 OAuth、授权过期或会话无效时，业务 API 必须拒绝；不得回落到邀请码、匿名请求或静态令牌。
- 当前知乎 OAuth 联调基线不含 PKCE、refresh token、撤销/解绑流程。Token 或应用会话过期后，应由用户重新授权。

> 回调地址：`https://api.anota.best/auth/zhihu/callback`。真实授权必须在知乎官方页面由用户本人确认。

### 可观测的求深 / 求异工作流

求深、求异不再用固定定时器伪造“第几步”。后台会发出结构化工作流事件，侧栏据此实时呈现：

- 当前真实阶段、已耗时与心跳；
- 逐条到达的知乎回答材料卡；
- 回答读取、摘要级/可引用性、立场判断与绑定状态；
- 超时或局部失败的原因与保守降级结果；
- 5 秒没有新事件时的“仍在等待响应”提示。

工作流事件具有 `requestId + seq` 门控，旧 Claim、旧模式或乱序事件不会污染当前界面。

## 使用方式

### 选中即问

1. 在任意网页中选中一句话。
2. 点击出现的 **「深读」** 入口，打开 Side Panel。
3. 在侧栏选择：

| 模式 | 问题 | 当前行为 |
|---|---|---|
| 求真 | 这句话靠谱吗？ | 多源检索、原文核对、来源评价、递归溯源与五态结论。 |
| 求深 | 背后是什么？ | 原理、概念与知识树；知乎回答仅为辅助材料。 |
| 求异 | 还有别的看法吗？ | 只搜索公开知乎回答，展示有来源的反例/补充视角；没有可靠来源不编造。 |

### 本文概览

页面右上角有一个可拖动的**放大镜悬浮球**：

1. 点击放大镜后，扩展才会在本地提取本文结构并请求声明识别；它不会在后台持续扫描网页。
2. 分析完成后，悬浮球显示发现的可验证声明数量。
3. 再次点击悬浮球，打开 Side Panel 的「本文概览」。
4. 选择任意 Claim，进入求真 / 求深 / 求异；页面中的对应位置会高亮定位。

## 三种分析模式

### 求真：证据闭环，而非“AI 打分”

```text
Claim + 上下文
  → Evidence Target：先确定要找什么证据
  → 多引擎检索与 URL 规范化
  → 来源身份分析、可信先验、事件兼容性与八维评分
  → 递归溯源、原文读取、逐源核对
  → 证据绑定与硬校验
  → 五态结论 + 可检查的来源网络
```

求真遵循以下原则：

- **存在 ≠ 相关 ≠ 支持**：每个来源都需要单独核对。
- **来源不等于独立证据**：转载与共享上游会聚类，不虚增证据数量。
- **结论必须绑定证据**：没有检索来源，不能把模型知识表述为“已核实”。
- **数字必须可回查**：结论包含数字时，系统会核对该数字能否在绑定证据中找到。
- **动态事实必须说明时间截面**：例如“截至某日期”的状态不能被写成无时间条件的绝对结论。

五态结论：无需验证 / 未找到可靠来源 / 来源不支持 / 部分支持 / 支持。

### 求深：知乎回答是辅助材料，不是权威结论

求深只把**公开知乎回答**作为辅助材料，用于补充概念解释、经验性视角和争议提示：

```text
理解 Claim
  → 生成知乎回答查询
  → 搜索知乎回答
  → 显示逐条到达的回答材料
  → 生成原理、概念与知识关系
  → 绑定辅助材料
```

- 当前 MVP 会如实标注“摘要级材料”；摘要不是原文，不能伪装为直接引用。
- 知乎回答属于用户观点，不代表知乎官方观点或客观事实。
- 单条回答失败不会阻塞主分析；界面会显示其读取/超时状态。

### 求异：不同观点必须有出处

求异只检索公开知乎回答，并把真实来源与立场判断绑定：

```text
理解 Claim
  → 搜索知乎回答
  → 筛选 / 去重
  → 读取回答正文
  → 判断支持、反例或补充视角
  → 绑定立场与出处
  → 输出遗漏维度
```

- 没有可靠知乎回答时，UI 会显示“未找到可靠的不同观点”，不会生成虚构的对立阵营。
- 立场候选会标注来源 URL 与可用的原文片段。
- 求异观点准备有局部超时保护；超时后保留已确认结果并继续主分析。

## 真实工作流可视化

求深 / 求异的侧栏工作流由后台事件驱动，不由 CSS 或固定计时器独立推进。

事件协议概念：

```js
{
  requestId,           // 当前分析请求
  seq,                 // 单调递增，面板拒绝乱序事件
  mode: 'deep' | 'differ',
  phase: 'zhihu_search' | 'answer_read' | 'stance_judge' | 'synthesis' | 'bind',
  status: 'start' | 'heartbeat' | 'candidate' | 'progress' | 'done' | 'error' | 'timeout',
  elapsedMs,
  completed,
  total,
  detail
}
```

UI 会展示：

- 当前阶段的呼吸光点、阶段说明与实际耗时；
- 纵向 workflow 连接线；
- 搜索到即显示的知乎回答卡片；
- 求异中从回答到“不同立场”的点亮状态；
- 软超时的黄色降级状态；
- `prefers-reduced-motion` 下的静态降级表现。

整体分析硬超时为 150 秒；任何阶段超过 5 秒没有新事件时，界面会显示仍在等待的原因，而不是卡在伪造的“第三步”。

## 隐私与数据范围

- 选中深读时，仅处理用户选中的文本、页面标题和 URL；求真为提取本页链接证据可能在本地读取当前文章 HTML。
- 本文扫描只在用户点击放大镜悬浮球后触发；不后台扫描、不采集浏览历史。
- V3.1 的 OAuth 仅用于登录门禁与昵称显示；默认不读取创作、关注、收藏夹或收藏内容。
- V3.2 的求深/求异只处理公开搜索到的知乎回答，不建立长期用户画像。
- 扩展中的第三方 API 请求经 Service Worker / Worker 代理处理；分发版不应包含第三方密钥或知乎 OAuth Token。

## 架构

```text
网页 Content Script
  ├─ 选区 / 放大镜悬浮球 / Hover 声明卡
  └─ CAPTURE_SELECTION / DETECT_CLAIMS
           ↓
MV3 Background Service Worker
  ├─ Active Selection 与消息路由
  ├─ OAuth 应用会话门禁
  ├─ 求真阶段直播（ANALYZE_STAGE）
  └─ 求深 / 求异工作流事件（WORKFLOW_STAGE）
           ↓
Analyzer + 检索/验证模块
  ├─ 求真：V2.5 证据定向、溯源、验证与绑定管线
  └─ 求深 / 求异：知乎回答专用检索与结构化阶段事件
           ↓
Cloudflare Worker（PROXY 模式）
  ├─ OAuth start / callback / 一次性 status 领取
  ├─ OAuth KV 短期 flow 与服务端会话
  └─ DeepSeek / Exa / metaso / 知乎开放能力代理
```

关键目录：

```text
.
├── manifest.json
├── src/
│   ├── core/
│   │   ├── content-script/  # 选区、SVG 放大镜悬浮球、页面提取、Hover
│   │   ├── background/      # MV3 Service Worker：消息、门禁、阶段广播
│   │   ├── auth/            # oauth-auth.js：应用 JWT 存取与 OAuth flow 轮询
│   │   ├── ai/              # analyzer、数据源、检索、验证、溯源、评分
│   │   └── utils/           # 消息类型、工作流事件、证据网络
│   └── sidepanel/           # 三 Tab 工作台、真实工作流剧场、结果渲染
├── scripts/                 # 本地配置生成与 smoke 验证
├── WORKPLAN.md              # 版本规划、决策、执行记录与验收账本
└── README.md
```

> Cloudflare Worker 可与扩展仓库分开部署。部署时需要绑定 OAuth flow/session 使用的 KV，并只通过 Worker Secret 配置敏感凭证。

## 运行与开发

### 加载扩展

1. 打开 Chrome：`chrome://extensions`
2. 打开「开发者模式」。
3. 点击「加载已解压的扩展程序」。
4. 选择本仓库根目录（其中包含 `manifest.json`）。
5. 在扩展详情中打开 Side Panel，或在网页中选中文本后触发「深读」。

改动扩展代码后，在 `chrome://extensions` 点击重新加载，再刷新测试页面。

### 模式

| 模式 | 适用场景 | 认证与密钥 |
|---|---|---|
| `PROXY` | 分发 / 集成环境 | 必须完成知乎 OAuth；第三方密钥与 OAuth Token 留在 Worker。 |
| `DIRECT` | 本地开发 | 使用本地开发凭证；不经过 OAuth 门禁。不得用于分发。 |

当前生成的 `src/core/generated-config.js` 为 PROXY 示例配置，指向：

```text
https://api.anota.best
```

该文件由配置生成脚本产生，包含代理地址但不应包含真实第三方密钥。

### 验证

```bash
node scripts/smoke-search-advise.js
```

该脚本是仓库内的 smoke 回归，不等同于完整浏览器 E2E。各版本还包含临时的行为级验证脚本；详细证据与人工验收要求见 [`WORKPLAN.md`](WORKPLAN.md)。

## 当前边界与已知限制

- OAuth 目前是黑客松联调基线：不包含 PKCE、refresh token 或撤销/解绑能力。
- 用户需要亲自在知乎授权页确认；自动化不能替代该确认。
- 知乎 `/user` 资料字段不稳定：昵称获取失败时不阻断登录，界面会显示“已授权知乎账号”。
- 求深当前的知乎材料可能是摘要级；只有可验证正文才能作为直接引用。
- 由于 Chrome 开发者模式扩展注入限制，浏览器端自动 E2E 可能受环境影响；请以 Chrome 人工验收为准。
- 本项目的历史 V2.8 邀请码说明仅保留在版本记录中；运行时登录机制已迁移为 OAuth-only。
